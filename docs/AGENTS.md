# Documentation context

Documentation records decisions and evidence; it must not become a speculative second system.

- Keep `docs/progress/CURRENT.md` concise and current; replace stale state instead of appending.
- Append session outcomes to `SESSION_LOG.md`.
- Add an ADR only for a durable decision with alternatives and consequences.
- Cite the exact subject/rubric section for normative claims.
- Mark interpretations and assumptions explicitly.
- Do not edit PDFs under `docs/sources/`.
- Update the evaluation matrix when behavior is proven by a test or command.
- Update teaching notes after a slice is understood, not before code exists.
